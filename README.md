//Learning summary
With merge you get to preserve all history of where changes came from,
while in a rebase you get a more linear project history rather than dealing with
commits that may just be progress points and not add any meaning to the project as
a whole to keep the commit message around. With the use of squash we were able to clean
up our commit messages and get rid of ones that did not contribute to the understanding
of how each iteration fit with one another and what was implemented with each iteration. 

In the git history for each for feature 1 and feature 2 there were multiple functions
and ideas being implemented, while in feature 3 it was focused on one main feature that
needed to be continued working on and bug fixed. For feature 3 implementing the squash feature
allowed us to clean up the comments and make the flow of added features more clean and 
understandable. 

I would use merge if there were many features added in one branch in order to get a more clear
understanding of how and where things were implemented. Rebase seems better to use if the branch 
adds a feature that can be summed up into one main theme or message where many implementations do 
not need to be traced.
